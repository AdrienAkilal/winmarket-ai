2. CONTEXTE ET ENJEUX
──────────────────────
La Communauté d'Agglomération Val de Rive regroupe 18 communes et
90 000 habitants. Ses services administratifs produisent et archivent
chaque année un volume documentaire considérable : délibérations du
conseil communautaire, arrêtés, marchés passés, règlements d'urbanisme,
comptes rendus de commissions, courriers réglementaires, notes internes
et rapports techniques.

Ce corpus représente aujourd'hui environ 15 000 documents PDF et Word,
éparpillés sur plusieurs espaces de stockage (serveur de fichiers NAS,
SharePoint, GED partielle, emails archivés). Les agents des services
marchés, urbanisme et juridique consacrent en moyenne 2 à 3 heures par
jour à la recherche documentaire, sans garantie de retrouver la version
à jour ou la source faisant référence.

Dans le cadre de sa feuille de route numérique 2024-2027, la DMN
souhaite expérimenter un assistant documentaire conversationnel reposant
sur les technologies RAG et LLM pour permettre aux agents de :

  • Interroger le corpus interne en langage naturel
  • Obtenir des réponses sourcées avec citation des documents sources
  • Réduire le temps de recherche de 60 % en phase pilote
  • Disposer d'un outil accessible sans formation technique préalable

Le budget total alloué à ce projet est de 72 000 € HT sur 4 mois.
Ce budget inclut la conception, le développement, le déploiement, la
formation et le rapport d'évaluation. Il est non extensible.

3. PÉRIMÈTRE FONCTIONNEL ATTENDU
──────────────────────────────────

3.1 Ingestion et indexation documentaire
  — Traitement du corpus initial : jusqu'à 15 000 documents (PDF, DOCX,
    XLSX, formats mixtes) issus du NAS et de SharePoint
  — OCR automatique pour les PDF numérisés (scans de délibérations, courriers)
  — Découpage intelligent du corpus (chunking adaptatif selon type de doc)
  — Vectorisation et indexation dans une base de recherche sémantique
  — Métadonnées associées : date, service émetteur, type de document,
    référence, statut (en vigueur / archivé / remplacé)
  — Interface d'administration pour l'ajout de nouveaux documents
    (glisser-déposer ou synchronisation depuis SharePoint)

3.2 Moteur de recherche et assistant conversationnel
  — Interface web de questions-réponses en langage naturel (français)
  — Réponse structurée avec : synthèse courte + sources citées + lien
    vers le document original
  — Mémoire conversationnelle sur 5 échanges successifs
  — Filtres optionnels : service, période, type de document
  — Indicateur de confiance visible pour chaque réponse
  — Mode "citation stricte" : la réponse ne peut contenir que du texte
    tiré mot pour mot des sources, sans reformulation LLM (mode audit)

3.3 Contrainte de périmètre dans le budget
  Les candidats sont invités à proposer un cadrage réaliste du volume
  traitable dans l'enveloppe. Un démarrage sur un corpus réduit de
  5 000 documents (services marchés uniquement) est acceptable si le
  candidat justifie la trajectoire vers l'industrialisation complète
  en phase 2 (hors périmètre du présent marché).

3.4 Interface et ergonomie
  — Application web responsive accessible depuis les postes Windows
    des agents sans installation locale
  — Authentification via l'Active Directory de la collectivité (LDAP /
    Azure AD selon configuration existante)
  — Interface épurée, sans jargon technique : accessible à des profils
    administratifs non informaticiens

4. EXIGENCES TECHNIQUES
─────────────────────────

4.1 Stack technique
  — Back-end : Python (FastAPI ou Flask) privilégié ; tout autre langage
    justifié est accepté
  — Base vectorielle : ChromaDB, FAISS, PostgreSQL pgvector, Qdrant ou
    équivalent open source
  — Modèle LLM : Mistral, Claude, GPT-4o ou équivalent accessible via
    API — les modèles locaux (Ollama) sont également acceptés
  — Front-end : React, Vue.js ou interface Streamlit pour la phase pilote
  — Hébergement : infrastructure cloud hébergée en Union Européenne
    (OVHcloud, Scaleway, Azure Europe — région française préférée)
    OU déploiement on-premise sur l'infrastructure VMware de la collectivité
    (spécifications fournies sur demande)
  — Containerisation Docker recommandée pour la portabilité

4.2 Sécurité et RGPD
  — Le corpus contient des données à caractère personnel (noms d'agents,
    signatures, données de marchés nominatives) et des informations
    sensibles de la collectivité
  — Le prestataire devra détailler les flux de données vers les modèles LLM
    externes et les mesures de protection associées (anonymisation,
    chiffrement des requêtes, contrat de sous-traitance conforme RGPD)
  — Journalisation des requêtes utilisateurs (qui a cherché quoi, quand)
    pour les besoins d'audit interne
  — Aucun stockage des données en dehors de l'UE

4.3 Indépendance technologique
  La collectivité souhaite éviter une dépendance forte à un fournisseur
  unique. Les candidats devront préciser :
  — La stratégie de remplacement du modèle LLM en cas de changement tarifaire
  — Les conditions de réversibilité (export du corpus vectorisé)
  — Les licences des composants utilisés (open source privilégié)
